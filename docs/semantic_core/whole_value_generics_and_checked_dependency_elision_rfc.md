## 1. 摘要与交付范围

提议把泛型形态相关的 `'` 从用户语法中移除：类型参数 `T` 默认表示满足声明约束的完整合法类型；抽象绑定 `x: T` 的名字表示完整 T，不需要根据实际类型再写 `'x`、`^x` 或其他占位帽子。

具体绑定的帽子规则不变。例如 `auto ^file = new File()` 中，`file` 仍是 payload 视图，`^file` 仍选择 owner handle。

另提出一项可独立实施的便利规则：对编译器已经验证的单源整值转交及纯结构包装／拆包装，允许省略源码中的依赖路由，但仍生成并验证供调用方消费的契约摘要。

两项提议必须分别审查、分别交付：

| 交付 | 改变什么 | 不改变什么 |
| --- | --- | --- |
| G：完整值泛型 | 统一 T 的含义，取消泛型名字及表达式的撇号占位 | 不自动省略依赖契约，不放宽所有权、权限或形态组合 |
| E：受检验的契约省略 | 对有限的已验证整值传递省略手写依赖路由 | 不省略消费、写权限、捕获或 unsafe 契约，不做全程序自动依赖推导 |

接受 G 不代表接受 E。G 不以完整借用容器支持或 E 的完成为前提。

## 2. 动机、收益与代价

现有模型区分 rigid `T` 与 morphic `'T`：前者限制根形态，后者保留完整的获准形态。绑定位置还需要 `'value`，部分表达式需要 `'(expression)` 或 `&'(expression)`。

这些写法解决了真实问题：具体裸名通常选择 payload，而泛型算法需要搬运未知形态的完整元素。本提案不删除这个语义区别，而是让泛型抽象身份承担它，不再要求程序员反复书写占位帽子。

预期收益：

- 泛型参数、绑定、成员、索引及返回使用一致的完整值模型。
- 内部引用／句柄能力随完整类型保留，不需要另加“权限适配符号”。
- 单态化不改变泛型源码中同一个名字的操作对象。
- 通过有限省略降低机械转发的标注噪音，保留真正的依赖边界。

明确代价：

- “所有裸名都表示终端 payload”必须收紧为具体句柄绑定规则。
- 原先依赖 rigid T 限制适用域的接口，需要保留或明确相应约束。
- 编译器仍需追踪抽象整值视图；删符号不等于删除全部内部元数据。
- 迁移涉及声明、推导、成员／索引、实例化及跨模块接口，不是文本替换。
- 依赖摘要可能构成接口内容；修改函数体也可能改变省略后生成的接口。

不承诺性能提升、编译器代码量必然下降或固定人日预算。

## 3. 核心语义：T 是完整类型，抽象名字是整值

### G1. 类型完整性

T 的实际类型保留完整的类型身份、形态、内部权限、可空性及相关语义事实。例如，满足相应约束时可有：

```text
T = i32
T = ^Node
T = &i32#
T = Option<^Node>
```

“T 不透明”针对泛型程序可观察和可执行的操作，不是让编译器擦除事实。T 也不代表“任何操作都适用于任何类型”。复制、转移、组合及访问仍受声明契约约束。

### G2. 抽象绑定不降帽

在泛型代码中，`x: T` 表示完整 T；当 T 实例化为 `^Node`，x 仍表示完整 owner handle，不重新解释为 Node payload。

```toka
// 目标语义示意；具体实例仍须满足现有消费契约的准入条件。
fn relay<T>(cede x: T) -> T {
    return cede x
}
```

这里选择“抽象整值绑定”规则，不退回 rigid T，也不让调用点替函数声明补权限。

类型替换不是源码文本替换。内部可以同时保存“绑定 x 是抽象整值”“实际类型为 ^Node”“消费契约为 cede”，无需生成 `x: ^Node` 再交给 Parser，也无需改写为 `^x: Node` 后丢失抽象身份。

直接书写具体句柄声明时，帽子仍在名字侧。本提案不由此开放具体形参 `x: ^Node` 的写法。

[Phase 2 历史记录 §1.5](../handle_grammar_phase2_spec.md)记载了既有名字侧根形态以及类型侧根形态的 E0494 拒绝。本稿调整的是抽象 T 的绑定解释，不是通过文本展开绕过该源语法检查；该历史文档本身不是最终 1.0 语法冻结。

### G3. 抽象身份按声明和表达式传播

视图按本次源码访问处、经过当时已知替换后的契约类型决定。不能用“当前函数是否为泛型”“字段最早曾以 T 声明”作全局豁免，也不能等单态化后再按物理类型重新决定是否降帽。

以下在泛型内部表示抽象 T 的位置都必须保持整值身份：

- 参数以及由它产生的局部绑定；
- 声明为 T 的字段及对应成员表达式；
- 元素类型为 T 的索引结果；
- 返回 T 的调用结果及相应转交。

```toka
// 目标语义示意。
shape Slot<T>(value: T)
```

泛型内部的 `slot.value` 若表示该抽象 T，就是整值，不再需要 `slot.'value`。这不授予字段移出资格，也不取消 remainder 清理责任。

在同一个泛型函数中，明确声明的 `auto ^file = new File()` 仍按具体帽子规则解释。D1 的冻结裁定如下：

| 源码检查时已知的契约 | 表达式 | 目标视图／准入 |
| --- | --- | --- |
| `s: Slot<T>`，T 仍抽象 | `s.value` | 完整 T；后续单态化不重新降帽 |
| 同上，未证明 T 有 unique 根 | `s.^value` | 拒绝无依据的具体 identity 选择 |
| `s: Slot<T>`，T 仍抽象 | `&s.value` | 新建对完整 T 槽位的借用，另验组合域 |
| `s: Slot<^Node>`，访问处已具体 | `s.value`／`s.^value` | 分别选择 Node payload／unique identity |
| 泛型函数中明确声明 `auto ^node = new Node()` | `node`／`^node` | 仍分别选择 payload／owner |

禁止的是对仅被证明为抽象 T 的对象使用没有根形态依据的具体 identity selector，不是禁止泛型函数出现帽子。若字段显式声明为 `^value: T`，其外层 unique 根已由契约给定，适用域成立时仍可选择 `s.^value`。`&x` 新建借用并不假定 x 原本具有引用根，不属于该 selector 禁令。

合法地从抽象整值推导局部时保留其抽象身份；从具体 payload 视图推导局部时不能恢复隐藏 owner。关联类型在定义检查时若仍是已成立的抽象类型投影，按抽象身份处理；已经解析为具体类型则按具体规则。解析失败不能冒充抽象类型。分支合流只合并该阶段成立的契约与来源，不以某次实例化改换视图。

具体调用者消费完整返回类型，但不继承 callee 内部的抽象名字豁免，接收绑定仍遵守具体帽子规则。表格只决定视图，不授权字段移出；借用、消费、PAL 和 remainder 清理继续独立验证。

### G4. 对外握手不消失

```toka
// 目标语义示意。
auto ^first = new Node()
auto ^second = relay(cede ^first)
```

调用方仍明确选择并转移具体 owner。不能将裸 payload 实参偷偷补成 owner handle；接收方帽子也不能把原本不是 owner 的结果升级为 owner。

`x: T` 与 `cede x: T` 的消费契约不同。不允许因为 T 实例化为 owning 类型就自动消费普通形参，也不允许复制 unique 或可变借用来满足整值传递。

抽象整值 `return cede x` 的解释不等于允许具体绑定的冗余或非法写法。现有具体 return/source 规则继续有效；没有新增 `-> cede T`。

保存传入资源的容器入口应声明消费性形参，例如目标写法 `push(self#, cede item: T)`，不是无消费契约的 `push(self#, item: T)`。当前 [Vec](../../lib/std/vec.tk) 的 push／insert／set 和 [HashMap](../../lib/std/hashmap.tk) 的 insert 已声明相应的 `cede` 形参，去掉撇号不要求新建自动消费通道。

读取路径另见同一 Vec 文件中的 `borrow`／`borrow_mut`：它们已使用具名返回形式 `-> &item: T`／`-> &item#: T`，并声明 `effects: &item <- self`。这证明既有返回写法和依赖契约存在，不等于证明新模型的整值元素借用已实现，也不能把返回绑定的例子当成形参准入的独立证明。G 实施后须按 G5 重新验证选择对象、返回类型及依赖；旧模型下可能面向 payload 的读取不能冒充新模型的完整 T 借用资格。

T 为 Copy 标量也不取消显式消费契约：具名实参仍按 cede 规则显式交接并失效，合格临时值保留既定豁免；若要保留源值，应使用已成立的复制／Dup 操作产生合法的新值，不能让编译器隐式插入 Dup。没有 cede 契约的普通形参不能因输入是临时资源就自动变成消费性参数。

## 4. 借用与类型构造：保留能力，不以 unsafe 绕过规则

### G5. 对完整 T 的借用仍用普通语法

```toka
// x: T；目标语义示意。
auto &t = &x
```

`&x` 借用 x 对应的完整 T 存储；通过 t 访问到抽象 T 边界即停止，不继续穿透 T 的实际内部帽子。该借用不自动赋予移出 T 的权力。

在现有合法组合域内：

| T | 完整 T 的借用类型 |
| --- | --- |
| Node | &Node |
| ^Node | &^Node |
| &Node | &&Node |

本稿明确不采用引用幂等折叠：T 为 `&Node` 时，新建对完整 T 的借用得到 `&&Node`，不归一化成 `&Node`。外层借用指向存放 T 的槽位，内部引用仍指向原来的 Node；折叠会把这两种不同存储关系混同。此处规定的是显式借用构造，不把普通参数捕获机制当作另加一个类型层。

依据与状态：[候选模型 §2.3—2.4](handle_morphology_candidate_model.md)分别描述参数捕获不新增类型层，以及 `borrow(handle(&T)) = &&T`；[Phase 2 历史记录 §1.5](../handle_grammar_phase2_spec.md)区分全局合法多层类型与 formal-root 准入；[当前类型分类器](../../src/Type.cpp)允许两层 managed 链的外层为 Reference。这些是设计参考及实现依据，前两份文档明确处于候选／历史状态。本稿的设计冻结依据本任务的独立裁定，不由这些引用自动推出，也不证明新泛型规则已实现。

因此，旧 `&'T` 可在目标模型中由 `&T` 表达；旧 `&'(items[index])` 可由对抽象 T 索引结果的普通借用表达。必须检查解析后的完整类型及实际借用存储，不能仅靠相同 payload 输出证明等价。

这不保留“泛型对不透明 T 自动剥帽访问内部 payload”的隐式能力。需要访问内部时，必须通过明确操作或约束表达。

访问层级须按操作数视图区分：抽象 T 的成员／方法操作只使用声明可用的契约，不因实例化揭示内部句柄就自动选择其深层 payload；具体绑定继续执行具体帽子规则。两个引用可能最终读到相同 Node，但其描述符存储、可失效路径与借用关系仍可能不同，不能由一次相同的读取结果推导类型等价或“没有解引用能力”。

再次写 `&x` 时也先确定 x 当前选中的视图，不能对整个物理类型机械再叠一层。这与不折叠并不矛盾：前者决定“本次借用选择哪个槽位”，后者规定“选定完整 T 后，不抹掉它内部已有的引用层”。若实际选择的是上一次引用的 identity 槽位，再借用确实会增加一层；每次新增构造均须满足组合域。已证明 T 可被借用一次，不等于证明任意次数的借用都合法。无法证明的构造应在 Sema 的定义／实例化验证中拒绝，不延迟到 CodeGen 才发现非法深度。

### G6. 构造能力与适用域分开

`*T` 与 `&T` 都构造包裹完整 T 的类型，但适用域不同。保留当前 `SoulOnly`、`BorrowExtendable`、`RawExtendable` 等必要约束的语义；源拼写只作对应迁移。

```toka
// 目标源拼写示意。
where:
    T: morphology borrow_extendable
```

泛型替换不能把抽象 T 当成一个新的 nominal 包装层，借此规避连续帽子组合检查。`*^Node` 等现有非法组合不因去掉撇号或进入 unsafe 而合法。

`*'T` 到 `*T` 只在原有合法域内主张等价。不扩大 raw 构造、raw_take、initialized extent 或安全借用保证。若要改变全局组合域，必须另有明确设计决定。

## 5. 权限与三类责任

### G7. 外层操作权限不能改写内部能力

必须分开：

- 修改存放 T 的槽位；
- 通过 T 内部句柄修改 referent；
- 重绑定句柄 identity。

T 为 `&i32` 时，外层对象或字段可写不能升级内部 referent。T 为 `&i32#` 时，内部能力不能反向授予外层槽位修改或重绑定权限。

以无名完整类型位置的引用写法为例：

| 类型写法 | 引用目标 i32 可写（P） | 引用句柄可重绑定（H） |
| --- | --- | --- |
| `&i32` | 否 | 否 |
| `&i32#` | 是 | 否 |
| `&#i32` | 否 | 是 |
| `&#i32#` | 是 | 是 |

`&i32#` 的尾部 `#` 描述被引用的 i32 可写，不是 `&` 句柄可重绑定；`&#i32` 的帽侧 `#` 描述引用句柄可重绑定，不授予 i32 写权。两者是不同层的能力，实际操作仍须满足来源、所选视图及 PAL 检查。这张表不开放具体形参的类型侧帽子写法，也不以类型标记凭空授予源绑定权限。

当 `T = &i32#`，i32 可写是完整 T 内部已有的引用能力。外层 `x#: T` 请求的是存放完整 T 的槽位可写，不是再次授予 i32 写权；若 `T = &i32`，同一外层请求也不能把其内部 i32 升级为可写。

D2 采用符号化的 **WholeSlotWrite（完整槽位写请求）**：`x#: T` 请求修改 x 所表示的完整 T 槽位，不直接把实际 T 的 H／P 属性置真。这个名称描述语义要求，不要求新增用户符号或特定内部类。

| T 的实例 | 整值赋值的对象 | x 捕获 caller 槽位时所需的既有授权 | 不因此获得 |
| --- | --- | --- | --- |
| i32 | 整数值槽位 | 该值的 P 写权及调用点明确请求 | 其他对象的写权 |
| ^Node | 存放 unique identity 的槽位 | 所选 owner identity 的 H 重绑定权及明确请求 | Node payload 写权、绕过旧值清理的权限 |
| &i32 | 存放引用描述符的槽位 | 所选引用 identity 的 H 重绑定权及明确请求 | 内部 i32 的写权 |

请求不是权限来源。具体调用方必须选择正确的槽位并给出已有权限所允许的请求，例如已支持的 raw identity 请求 `*#p`；仅有 `p#` 这一 payload 请求不能满足对 handle identity 的替换。其他帽子遵守同一要求，不因进入泛型而默认获得 H。

真正独立的新局部槽位可以由显式可写声明、合法初始化／所有权接收及 binding plan 建立本地 WholeSlotWrite；捕获参数或别名则必须从实际被借用的槽位取得授权。新名字、auto、身处泛型或“看起来独占”均不能单独证明该权力。

外层借用的权限按以下对象解释，T 实参自身保持完整且不被改写：

| 源形式（在相应获准位置） | 权限作用对象 |
| --- | --- |
| `&x: T`／无名 `&T` | 通过外层只读借用访问完整 T |
| `&x#: T`／无名 `&T#` | 通过外层借用写完整 T 槽位；创建时必须证明该槽位允许 WholeSlotWrite |
| `&#x: T`／无名 `&#T` | 外层引用 handle 自身的重绑定，不授予对 T 的写权 |
| `&#x#: T`／无名 `&#T#` | 两项分别声明、分别验证 |

例如 T 为 `&i32` 时，`&T#` 可以在获准的内层引用槽位替换完整引用值，但不能改内部 i32，也不因此获得对新外层引用 handle 的重绑定权。用语义结构看，它是对完整 T 的可写借用，不是把类型参数 T 本身改造成另一个可写类型；不能通过源码字符串展开或原地修改共享 Type 对象来实现。

实例化把 WholeSlotWrite 映射到所选存储已有的权限：对 handle 槽位可能需要 H，这不等于由 T 内部能力向外升级。合法 RHS、消费／复制、旧目标清理、PAL、重叠拒绝、实际依赖更新及失败回滚仍须成立。源可见和 source-hidden 形参必须表达同一要求；AST 具体布局留给实现，不再影响权限对象的设计选择。

### G8. 来源、存储和清理不得合并成一个 Anchor

区分以下事实，但不要求把 PAL 重构成一个新三元组：

1. 值携带的实际借用来源；
2. 存放该值或描述符的存储路径；
3. 移动失效区域及清理责任。

它们不保证是一条固定层级链，也不保证各只有一个对象。

转交 x 保存的引用值时，传递其已有来源；新建 `&x` 时，建立对 x 对应存储的借用。后者即使在 T 为 i32 时也存在，不能按“类型里没有 &”关闭。

拥有值移动后的结果，不应仅因来自旧绑定就借用依赖那个已失效绑定。反过来，借用局部描述符存储时，也不能直接跳到最深 pointee 而忽略局部存储寿命。

同类型的两次调用可以具有不同实际来源。泛型缓存不能保存并串用某次调用的具体 root identity。

## 6. 交付 E：受检验的依赖契约省略

此节在 G 之外单独讨论和接受。不引入新的依赖路由拼写，不取消现有显式路由能力。

### E1. 仅免书写，不免验证

优先级如下：

1. 已显式声明的契约继续验证；省略机制不得静默替换它。
2. 结果已证明不携带逃逸依赖时，不凭空创建依赖。
3. 未写路由且满足受限省略规则时，生成经过验证的摘要。
4. 不满足省略规则时要求显式契约；显式契约也必须可证明，不能使非法程序合法。

不按返回类型与输入类型相同猜测来源，不默认依赖所有输入，不默认偏向 self。

### E2. 首批只有两类操作

- 单源整值转交：正常返回路径上的相关结果来自同一已验证输入来源。
- 纯结构包装／拆包装：使用已知的结构性构造或提取，保持相应 payload 的来源，不调用未知行为替代结构操作。

“单源”依据已验证数据流，不是统计参数表中出现几个 T。多个可能来源的选择不属于首批省略范围。

定义体中已证明为空 payload 的变体，例如 None，可以没有对应依赖；Some 中的 T 保留自身来源。混合返回在调用点缺少足够的既有变体事实时，摘要／账本可以保守保留各合法路径的依赖并集，不能仅因运行时结果可能为 None 就删去依赖。

本提案不承诺所有调用者进入 None 分支后都能精确解除来源，也不禁止复用已有局部 match 精化。单一来源与空来源的合流不因此自动排除于省略范围；能否精确解除与能否验证安全的省略摘要是两件事。未知不得当空，首批不要求建立新的全局枚举精化系统。

自定义 Dup、任意命名构造函数、raw 提取、回调及容器内部操作不因名字或返回类型相似而被认定为纯结构操作。

### E3. 不新增循环不动点或全调用图推导

首批不为省略路由新增循环分析。相关转交链跨越未证明的循环状态时，不适用省略；原有循环安全检查仍执行。

遇到调用，只能复用已完成的可信摘要及现有组合能力。不为满足省略而递归搜索未知函数体、放开递归摘要或进行全程序分析。没有可信契约时不能假定来源守恒。

### E4. 以下不省略

| 契约／行为 | 本提案政策 |
| --- | --- |
| 消耗性形参的 cede | 不省略 |
| 调用边界具名 source 的显式转移 | 不省略；既定临时值豁免不变 |
| 写权限、捕获方式、unsafe 前置条件 | 不省略、不推断授权 |
| 新建逃逸借用 | 保留显式依赖路由 |
| 多源选择 | 保留显式依赖路由 |
| 向已有外部对象存入依赖 | 保留显式流入契约 |
| 未验证的高阶调用或存储行为 | 不自动省略；也不能靠补一条声明替代缺失的合法性证明 |

### E5. 摘要是接口，不是调用点猜测

只在函数及相关正常返回路径通过验证后发布完整摘要；失败、递归未决或不完整状态不发布成功契约。

摘要描述参数化的输入／字段到结果的来源关系，调用时映射实际来源。不得把构建目录、AST 指针或单次调用 root 当作可复用接口身份。

泛型调用的摘要应用按以下职责划分，不预先规定新的求值引擎或序列化格式：

1. 验证本次类型替换及契约的适用条件，并把形式参数／字段路由映射到实际输入位置。
2. 对整值转交，传递实际输入所携带的已验证依赖；已证明无依赖的值对应空集合，未知事实不能当空。同一种 T 的不同实参可以映射到不同来源。
3. 对显式新建的存储借用，仍建立相应存储依赖；不能因为 T 为 i32 就关闭这类借用。

为生成特化代码，现有单态化流程可以取得并检查泛型函数体；这不等于接口摘要失效。调用方取得依赖契约不能以重新分析被调函数体为前提，必要的替换、摘要有效性验证和接口一致性检查仍须执行。符号化摘要与特化表示只要具有相同可观察语义，均不由本稿提前排除。

跨模块及 source-hidden 调用必须与源码可见调用一致。优先复用已有摘要／接口表示；如确需修改格式或语义键，必须作为 E 的明确差异审查，不能在本草稿中预先宣称无需变更。

由函数体生成的摘要可能随实现改变，因此需要可展示、可比较、可触发正确重验证。保留显式契约用于约束稳定接口。

没有函数体的边界只能消费已有可信契约；本提案不增加 extern 依赖语法，也不从目前可见的 Trait 实现集合反推永久公共契约。

### E6. 高阶函数不使用环境全集公式

map／and_then 的结果依赖只能通过回调已验证的结果契约组合。不能无条件并入所有捕获；用于计数但不流向结果的捕获不应成为结果依赖。

若结果实际借用了即将销毁的闭包环境，摘要不会延长环境寿命，程序仍须拒绝或由另一个已成立的拥有／保活契约解决。

pop 属于具有存储责任的提取，不是仅凭 `T -> T` 就能证明的 identity。本提案不为它新增槽位证明机制。

## 7. 非目标与不可越界事项

- 不重塑 PAL，不引入用户生命周期变元或统一 Anchor 穿透规则。
- 不取消依赖标注，不做任意函数的全自动来源推导。
- 不开放原先未资格化的 partial move、raw/managed 混合链或数组初始化。
- 不把完整 `Vec<&T>`、递归容器或 JSON 恢复捆绑为本提案前置工程。
- 不改变 raw_take、线程协议、carrier 布局、引用计数算法或具体帽子含义。
- 不以自由定理代替系统级来源、权限和清理验证；不声称与其他语言安全性完全同构。
- 仅处理泛型形态占位及整值选择用途的撇号；字符字面量（如 `'a'`、`'('`）及其转义规则不变，不对引号字符进行全局文本删除。
- 不自动兼容旧库 API；必要时按新规则迁移库，但不能仅因库测试失败就扩张编译器机制。

### 10.1 D1—D3 的审议约束

以下约束配合 G3、G7 和上述冻结裁定使用，不增加新的交付：

- **D1：视图选择不等于移动授权。** 不能由“表达式呈现完整 T”直接推出“允许移动”。若某个候选规则把外部 `slot.value` 定义为 payload，那么 `cede slot.value` 仍只能操作该 exact source，不能偷偷提取 owner。D1 的内外边界方案必须同时说明具体 owner 选择、读取／借用、转移及接收绑定；partial-move 与清理准入仍独立验证。
- **D1：核对现有选择语法，不凭空推断 Parser 缺口。** [当前语法说明 §8](../syntax_zh.md)已有 `d.^p` 与 `d.p` 的区分，[成员解析器](../../src/Parser/Parser_Expr.cpp)处理点号后的帽子。实施时应分别核对 Member／Index／Call 的相关写法、抽象身份传播与实际移出资格；不能因为没有证明 `^(s.value)` 可用，就推导所有外部字段只能通过方法访问。目标视图按 G3 的冻结裁定确定，现有实现对该目标语义的支持仍须验收，不在此提前宣称运行通过。
- **D2：不能借用 C 的解引用记法。** Toka 的 `*p` 选择 raw handle identity，不是通过引用写 payload 的通用操作；该区别见[项目规则中的帽子说明](../../rules.md)及[带写入断言的 payload／rebind 对照](../../tests/pass/out_param_handle_rebind_control_test.tk)。`&x: T` 是既有绑定写法，不是本稿新增语法；本稿讨论的是它在完整值泛型模型下的解释：裸 x 访问借用的完整 T 层，写入资格按 G7 分层验证。`&T#` 不能笼统解释为升级 T 最深处的 payload：当 T 自身是只读引用时，必须保留其内部限制。
- **D2：替换示意与合法源码分开。** 使用 `x#: T`、`&x#: T` 并注明 `T := &i32` 来讨论层级；不要把内部类型替换结果写成已获准的具体具名声明 `x#: &i32` 或 `x: &i32#`，借此绕过 G2 的源语法边界。
- **D2：源拼写、AST 归属、权限对象分别列明。** [当前类型 token 处理](../../src/Parser/Parser.cpp)区分帽侧 `IsSwappablePtr` 与名字／类型 token 的 `HasWrite`。不得将 `&T#` 直接等同于 `&#T`，或把 H 重绑定与 P 写权限互换；也不预设“后缀 # 永远属于最左构造器”。内部 AST 中存在属性节点，不等于该节点对应的独立源码拼写获准，更不授权修改 T 实参内部权限。实施时应保留 G7 的权限对象和 T 身份，不能让某种 AST 外形反向决定语言规则。
- **D3：未知事实不是否定证明或清理授权。** 无约束 T 不获得未经证明的复制权，但不能因此记录为 `ProvenNonCopy` 或断言一定需要 Drop。保留符号化要求／未知状态，并通过实例化及现有验证解析具体能力与清理计划。
- **D3：Dup 与隐式 Copy 不可互换。** `@Dup` 提供显式复制操作，不能仅凭该约束就让 `(x, x)` 隐式复制；需要复制时使用合法的 Copy 规则或显式 `.dup()`。同样，不为所有未知 T 无条件生成析构调用。

讨论反馈请按“具体程序／预期视图／权限／来源／清理结果”提出，区分：设计矛盾、已有实现缺陷、迁移工作和可后续增加的便利。不得把局部测试绿色等同于 RFC 已接受。
