`main` commits.

`release-gate-<target>` artifact for each target. `release_gate.py` exits
nonzero if any of its thirteen stages fails or if its tracked source worktree
is dirty; the successful run is therefore the qualification result for this
specific revision only.

## Native first-hour replay

On a clean macOS arm64 temporary directory, using only the extracted RC1
archive's `bin/` and `lib/`, this sequence passed:

```text
toka doctor
toka new replica_smoke
cd replica_smoke
toka add regex
toka run
TOKA_OFFLINE=1 toka fetch
TOKA_OFFLINE=1 toka run
toka check --json <ownership-failure-fixture>
```

The public registry resolution and offline lock replay preserved the same lock
digest. The final JSON check returned the expected nonzero status and
`E0440` diagnostic envelope.

This verifies the documented relative-name project flow. RC1's archive does
not include the later `toka new <absolute-path>` fix; that correction first
appeared on post-RC1 `main` and must be qualified under a new candidate label.

## Evidence boundary

The GitHub Actions artifact metadata for the four `release-gate-*` reports is
public and unexpired, but downloading artifact contents requires authenticated
GitHub access. When exporting a formal release dossier, retain the four JSON
reports alongside this audit and verify each report's revision, version label,
`source_dirty=false`, and all thirteen passing stages. No later `main` commit
may reuse RC1's reports or archives.
