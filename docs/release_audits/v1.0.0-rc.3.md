# v1.0.0-rc.3 qualification audit

**Status:** Historical, non-qualified tag. `v1.0.0-rc.3` does not satisfy this
record: its tag gate failed before summary, archive, draft, or publication.
The immutable tag is retained for audit and cannot be promoted or reused.

## Required record

Before an RC3 tag may be authorized, add:

- the immutable candidate SHA and unchanged compiler-interface compatibility
  key;
- one passing `toka.release-gate` v2 report for Linux x64, Linux arm64, macOS
  x64, and macOS arm64, each with `source_dirty=false` and
  `version_label=v1.0.0-rc.3`; the generated summary must verify that all four
  reports bind one candidate SHA and the fixed thirteen-stage set;
- one passing TaskHandle Lifecycle v2 conformance record per target, all bound
  to that SHA and the same v2 contract digest;
- the hosted run and artifact references; and
- SHA-256 digests plus clean installed first-hour replay results for all four
  final release archives, including `toka preview`.

The tag workflow may create only a **draft** after it has gathered and verified
all four native archives and `SHA256SUMS`. It cannot publish automatically.
After clean first-hour replay is recorded, the protected promotion workflow
downloads and rechecks that exact draft asset set before making it public. The
withdrawn `v1.0.0-rc.2` tag is not an input to this audit.

Before using this workflow, repository administrators must configure the
`release-publication` GitHub Environment with required reviewers. This
repository file selects that environment but cannot establish its protection
policy itself.
