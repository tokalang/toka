命令行工具与构建

Toka 提供两个命令行工具：

  • tokac: 编译器。
  • toka: 项目管理与构建编排命令。

日常开发通常使用 toka。它负责包装编译器调用、包解析、构建元数据生成、测试、格式化和文档任务。

项目脚手架 (Scaffolding)

Section titled “项目脚手架 (Scaffolding)”

1. toka new <name>

Section titled “1. toka new <name>”

创建新的可执行项目目录，包含 src/main.tk、package.tk 和 build.tk。

2. toka new <name> --lib

Section titled “2. toka new <name> --lib”

创建新的库项目，入口模块为 lib/<name>/mod.tk。

3. toka init

Section titled “3. toka init”

在当前目录中初始化 Toka 项目。

开发与构建

Section titled “开发与构建”

1. toka run

Section titled “1. toka run”

通过 build.tk 构建当前项目，然后运行 target/debug 下最新生成的可执行文件。

2. toka run <file.tk>

Section titled “2. toka run <file.tk>”

编译并运行单个 .tk 文件，不要求当前目录是完整项目。

3. toka build

Section titled “3. toka build”

执行包解析、编译 build.tk，并由构建脚本生成配置好的目标。

常用选项

Section titled “常用选项”
  • -v, --verbose: 显示更多编译和构建输出。
  • -f, --forge: 启用实验性的 Forge 并行增量构建引擎。

测试与质量保证

Section titled “测试与质量保证”

1. toka test（Preview）

Section titled “1. toka test（Preview）”

发现 tests/ 目录下的 .tk 文件，针对项目和标准库路径逐个编译、运行，并输出简洁的通过 / 失败统计。这是实验性的源码树扫描器，不是 Toka 稳定的项目测试契约，也不能作为包发布资格命令；每个包必须说明自己的资格验证命令。

在 Windows 上，toka test 当前需要 Bash 兼容环境，例如 MSYS2 或 Git Bash。

2. toka fmt

Section titled “2. toka fmt”

格式化项目内的 Toka 源文件。

文档生成

Section titled “文档生成”

toka doc

Section titled “toka doc”

从带有 /// 注释的公开声明生成 docs/API.md。

包管理与注册表

Section titled “包管理与注册表”

包元数据存放在 package.tk 中。注册表使用经过审核的静态 catalog：一个包 release 由带 tag 的 GitHub Release archive 及其 SHA-256 catalog 条目组成。 CLI 提供包搜索、依赖记录和 archive 创建能力，但不会假装存在无需授权的公开上传服务。

toka search <keyword>

Section titled “toka search <keyword>”

搜索配置好的 Toka 包注册表。

toka publish

Section titled “toka publish”

创建当前包的 release archive；它本身不会上传到公开注册表。应将 archive 发布到带 tag 的 GitHub Release，再提交记录 URL 与 SHA-256 的审核 catalog 条目。 完整流程参见包复刻指南。

toka add <url_or_name>

Section titled “toka add <url_or_name>”

向当前项目添加包依赖，并更新 package.tk。

工程清理与依赖

Section titled “工程清理与依赖”

toka clean

Section titled “toka clean”

清理项目构建产物，例如 target/、build/、.toka_build_exe 和依赖缓存目录。
