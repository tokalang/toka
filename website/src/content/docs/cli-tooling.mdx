Toka ships with two command-line tools:

- `tokac`: the compiler.
- `toka`: the project manager and build orchestration command.

For day-to-day work, you usually use `toka`; it wraps compiler invocation, package resolution, generated build metadata, tests, formatting, and documentation tasks.

## Project Scaffolding

### 1. `toka new <name>`
Creates a new executable project directory with `src/main.tk`, `package.tk`, and `build.tk`.

```bash
toka new my_app
```

### 2. `toka new <name> --lib`
Creates a new library project with a `lib/<name>/mod.tk` entry module.

```bash
toka new my_lib --lib
```

### 3. `toka init`
Initializes a Toka project in the current directory.

---

## Development & Build

### 1. `toka run`
Builds the current project through `build.tk`, then runs the newest executable from `target/debug`.

### 2. `toka run <file.tk>`
Compiles and runs a single `.tk` file without requiring a project directory.

### 3. `toka build`
Runs package resolution, compiles `build.tk`, and lets the build script produce the configured target.

### Useful Options

- `-v`, `--verbose`: show more compiler and build output.
- `-f`, `--forge`: enable the experimental Forge parallel incremental build engine.

## Testing & Quality Assurance

### 1. `toka test` (Preview)
Discovers `.tk` files under `tests/`, compiles each test against the project and standard library paths, runs the resulting executables, and prints a compact pass/fail summary. This is an experimental source-tree scanner, not Toka's stable project-test contract or a package release-qualification command. Each package must document its own qualification command.

```bash
toka test

# Output:
# Running Toka tests...
#   Testing tests/pass/math_test.tk ... [OK]
# Test Results: 1 passed, 0 failed
```

On Windows, `toka test` currently expects a Bash-compatible shell such as MSYS2 or Git Bash.

### 2. `toka fmt`
Formats Toka source files in the project.

## Documentation

### `toka doc`
Generates `docs/API.md` from public declarations documented with `///` comments.

```toka
/// Calculates the sum of two numbers.
pub fn add(a: i32, b: i32) -> i32 {
    return a + b
}
```

## Package Management & Registry

Package metadata is stored in `package.tk`. The registry uses a reviewed,
static catalog: a package release is a tagged GitHub Release archive plus its
SHA-256 catalog entry. The CLI provides package discovery, dependency records,
and archive creation without pretending that an unauthenticated public upload
service exists.

### `toka search <keyword>`
Searches the configured Toka package registry.

```bash
toka search ink

# Output:
# Search Results:
# ---------------
# toka-ink (0.2.1)
#     Terminal UI component library for Toka language
```

### `toka publish`
Creates the current package's release archive. It does not upload to the public
registry by itself. Publish the archive in a tagged GitHub Release, then submit
the reviewed catalog entry that records its URL and SHA-256. See the
[package replication guide](https://github.com/tokalang/toka/blob/main/AGENTS-USER.md)
for the complete workflow.

### `toka add <url_or_name>`
Adds a package dependency to the current project and updates `package.tk`.

## Housekeeping

### `toka clean`
Removes project build artifacts such as `target/`, `build/`, `.toka_build_exe`, and dependency cache directories.
