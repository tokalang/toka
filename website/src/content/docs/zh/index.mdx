## 设计目标

Toka 从两个底线出发：可预测的零成本性能，以及强静态安全。在这两个前提下，Toka 追问的是：系统代码能否在不隐藏真实系统语义的前提下，更直接、更紧凑、更可维护。

Toka 不以“最少语法”为目标。它追求的是：在真实系统语义不被隐藏的前提下，触摸到所需的最小表层。所有权转移、可变性、重绑定、可空性、错误传播、异步挂起、FFI 边界，以及表示层访问，都应该在真正发生作用的位置可见。

<CardGrid stagger>
	<Card title="性能是底线" icon="rocket">
		Toka 没有垃圾回收器，并通过 LLVM 进行 AOT 原生编译。资源成本和表示成本应当保持可见、可预测，而不是被默认运行时层遮住。
	</Card>
	<Card title="静态安全是底线" icon="shield">
		资源流、借用、可空性、重绑定和清理通过 PAL、`cede` 等显式契约接受检查。当某种关系无法被局部证明时，Toka 应当保守拒绝，而不是把完整生命周期演算压到日常代码表层。
	</Card>
	<Card title="Payload 与 Handle 分离" icon="puzzle">
		裸名操作对象 payload。只有代码确实需要借用、拥有、共享、转发或重绑定 handle 层时，才使用 `&`、`*`、`^`、`~` 等帽子。
	</Card>
	<Card title="复杂性必须有职责" icon="star">
		每一份表层复杂性都应该证明自己揭示了一个真实系统边界；否则这个边界就会变得隐式、遥远，或者更难审计。
	</Card>
	<Card title="内建项目工具链" icon="setting">
		`toka` 命令围绕 `package.tk` 和 `build.tk` 管理项目创建、单文件运行、包解析、构建编排、测试、格式化和文档生成。
	</Card>
</CardGrid>
